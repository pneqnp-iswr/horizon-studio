# Official Horizon .hmod Verification (HS-001)

## Scope

The CLI `verify` command generates an experimental Studio `.hmod`, runs the **actual external official** `cargo horizon-mod check <file> --json`, parses the tool's report, verifies the reported archive SHA-256 and byte count, and exits nonzero if the tool fails or is missing.

It does **not** prove the local binary's source revision, validate live rendering, or start Horizon. A successful official static check is not a real-game smoke test.

## Installation with a pinned revision

Official upstream: https://github.com/horizon-rust/horizon.

Reference engine revision from the 2026-10-30 audit: `d2186eb9aa022a64a8b26e6989a04e44fba99ee7`. This is a documented baseline, **not** proof that this checkout or binary was installed locally.

Install the official Cargo subcommand using a specific reviewed revision, not an untracked moving branch:

```sh
cargo install --git https://github.com/horizon-rust/horizon --rev d2186eb9aa022a64a8b26e6989a04e44fba99ee7 cargo-horizon-mod
```

Check a Studio project:

```sh
python horizon_cli.py verify examples/ruby_demo.hstudio.json --json \
  --validator-revision d2186eb9aa022a64a8b26e6989a04e44fba99ee7 \
  --evidence dist/ruby-official-evidence.json
```

If `cargo` is not available on PATH, provide `--validator-bin /path/to/cargo`. To use the `cargo-horizon-mod` executable directly, add `--direct-validator --validator-bin /path/to/cargo-horizon-mod`.

Do not supply untrusted executables as validators. The program is executed as an OS process, without a shell.

## Evidence fields

- `stage=official` is only a validation-stage identifier.
- `ok=true` requires process exit 0, JSON `ok=true`, correct kind `mod`/API `0.2`, and a matching SHA-256 and size for the exact generated `.hmod`.
- `sha256` and `size` refer to the package bytes generated by Studio.
- `declared_validator_revision` is **user-supplied provenance**, not cryptographic proof of the installed validator build.
- `command` records the invocation; the temporary directory path expires at process exit.
- A missing, timed-out, crashed, incompatible or rejecting validator returns `ok=false` and a nonzero CLI exit code.

## Pinned checker in GitHub Actions

The workflow [Official Horizon content-mod check](../.github/workflows/official-content-check.yml) checks out the audited engine revision `d2186eb9aa022a64a8b26e6989a04e44fba99ee7`, **verifies Git HEAD against that immutable SHA**, compiles the actual `cargo-horizon-mod` package from that source, and invokes `horizon_cli.py verify` on **every** `examples/*.hstudio.json`. It runs on pull requests and pushes to `master` that touch the generator, and uploads `dist/official/` as a GitHub Actions artifact containing the toolchain versions, checker binary hash, one raw JSON report and one attestation per example.

The normal Python CI remains fast and does not substitute for this Rust-tooling integration. The pinned workflow intentionally fails rather than reporting unsupported or invalid content as verified. It does not need Minecraft assets and does not run a game.

Only completed, successful workflow execution demonstrates an actual official checker run. A green Python unit-test matrix alone does not.

Recorded results, by engine revision and package hash, are kept in [COMPATIBILITY_EVIDENCE.md](COMPATIBILITY_EVIDENCE.md).

## Reproducing locally

```sh
git clone https://github.com/horizon-rust/horizon && cd horizon
git checkout d2186eb9aa022a64a8b26e6989a04e44fba99ee7
cargo build --locked --package cargo-horizon-mod
cd /path/to/horizon-studio
python horizon_cli.py verify examples/workshop_showcase.hstudio.json --json \
  --direct-validator --validator-bin /path/to/horizon/target/debug/cargo-horizon-mod \
  --validator-revision d2186eb9aa022a64a8b26e6989a04e44fba99ee7
```
