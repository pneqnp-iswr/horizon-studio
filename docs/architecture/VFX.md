# VFX Studio (HS-025, HS-026, HS-027)

**Rule:** the VFX Studio preview is a Studio preview. It shows what the effect data describes, rendered by Studio; it
never claims how, or whether, Horizon renders it. Every effect is marked *Studio preview — not in-game rendering*, and
the panel lists what the project's target engine can and cannot do with it.

## The model: `studio.vfx/1`

An effect is a canonical project object of kind `vfx` (stable `uid`, `id`, `props`). It is Studio authoring data: the
`.hmod` generator leaves it out, so adding an effect never changes a package (the Ruby demo with an effect still builds
the officially checked `ee3e1c87…`).

```json
{"schema": "studio.vfx/1", "name": "Impact Spark", "duration": 0.8, "loop": false, "seed": 1337,
 "emitters": [{"id": "sparks", "bursts": [{"time": 0, "count": 28}], "shape": {"type": "sphere", "radius": 0.12},
   "direction": {"axis": [0, 1, 0], "spread": 70}, "speed": [3.5, 7], "lifetime": [0.25, 0.6],
   "gravity": 9.8, "drag": 2.5, "stretch": 0.035, "blend": "additive",
   "size": [[0, 0.1], [0.7, 0.06], [1, 0]], "color": [[0, "#fff6c8"], [0.35, "#ffbe3d"], [1, "#b8320f"]],
   "alpha": [[0, 1], [0.8, 0.9], [1, 0]]}]}
```

Units are metres, seconds and degrees. Budgets: 8 emitters, 16 bursts per emitter, 512 particles per burst, 2,048 per
effect, 16 keys per curve. Validation reports each problem with a path and a code (`COUNT`, `ORDER`, `COLOR`,
`KEY_START`, `BUDGET`, …); the editor refuses a change that fails it and keeps the previous effect.

## Determinism

- **Random numbers:** `mulberry32`, one stream per emitter seeded with `seed + index·0x9E3779B9`, so adding an emitter
  never changes the others. Each particle draws seven numbers in a fixed order: position, direction, speed, lifetime.
- **Motion is closed-form,** with linear drag `k` and gravity `g`:
  `p(t) = p₀ + (g/k)·t + (v₀ − g/k)(1 − e^(−kt))/k`, or ballistic when `k = 0`. Scrubbing the timeline to any time is
  exact; there is no accumulated step error.
- **One model, two implementations:** `vfx_engine.js` in the editor and `studio_core/vfx.py` in the core. Tests check
  every particle of the Impact Spark against one fixture generated by the core
  (`tests/fixtures/vfx_impact_spark.json`; the largest difference measured is 1.7·10⁻¹⁶ m). On one machine the same
  seed gives bit-identical particles; across platforms the math libraries may round the last bit differently, so the
  tests compare to 10⁻¹² (Windows and Linux CI differ in the 16th digit).

## The editor

<img src="../screenshots/vfx-studio-1440x900.png" alt="VFX Studio at 1440 by 900: the effect list, a large pixel preview of an Impact Spark with an added smoke puff (orange sparks over grey smoke), the transport with play, restart, a timeline at 0.18 seconds with a burst mark and 40 particles, engine notes saying it is a Studio preview and that Horizon has no custom particle contract; on the right the effect fields, the emitter list (sparks, flash, smoke with particle counts and blending), template, add, duplicate, move and delete buttons, a budget line '41 particles, low, medium and high profiles fit', and the inspector of the smoke emitter" width="100%" />

Rail → **VFX Studio**: a large preview, a timeline, the emitter list and an inspector. There is no node graph: an
effect is a list of emitters, and that is what the editor shows.

- **Effects.** Create (Impact Spark preset), delete, rename; name, seed, duration and loop.
- **Emitters (HS-026 slice).**
  - Add one from a template (sparks, flash, smoke puff); duplicate, move up or down, delete (at least one stays, at most
    8).
  - Select an emitter to edit it.
- **Emitter inspector.**
  - Bursts (time and count, up to 16), shape (point or sphere, radius), direction axis and spread, speed and lifetime
    ranges, gravity, drag, trail, and blending (additive glow or alpha smoke).
  - Three curves over a particle's life: size, opacity and colour. Each is a keyframe table (life 0–1 and value) with
    add and remove; the colour curve also shows a gradient strip.
- **Timeline.** Play, pause, restart and scrubbing to any time; it is exact, because motion is closed-form. Burst
  times are marked on the track.
- **Budgets.** The particle count of every burst of every emitter against three quality profiles (low ≤ 256, medium ≤
  1,024, high ≤ 2,048). Above 2,048, validation refuses the change.
- **Validation and history.** Every change is validated first; a refused change marks the field and changes nothing.
  Each accepted change is one step of the project's shared history (HS-020): undo and redo, autosave, save, reopen,
  and restart all go through it.
- **Reduced motion.** With reduced motion the preview never starts by itself.

## What Horizon can do with it (audited at `3c1d4b39`)

Read from the source, not assumed:

- **Shader packs (`.hshader`).**
  - Format: a zipped folder with `horizon-shaders.toml` and WGSL (`crates/horizon-shader-api/src/package.rs`).
  - The manifest has three kinds of stage: `sky`, `material` and full-screen `post` passes
    (`crates/horizon-shader-api/src/manifest.rs`).
  - The guide calls the format "API 0.1, experimental" (`docs/shaders.md`, read at `3a5ac7ff`).
  - There is **no particle stage**, so a shader pack cannot define particles.
- **`GameLevel::native_send_particles(options, state, at, spread, speed, count) -> bool`** (native hooks, API level 11;
  `crates/horizon-client/src/game/native_hooks.rs` lines 814–858). It queues **vanilla** particle types in an
  **authoritative** level only:
  - block types need a block state; item, trail and vibration particles are refused;
  - `ParticleOptions` carries `color`, `to_color` and `scale` (dust types);
  - the return value means *accepted, not delivered*.

  It is available to native mods only (HS-010: isolated build, explicit approval of Horizon's native-code trust
  boundary).
- **The pin `d2186eb`** has neither.

So the engine contract `render.custom_particles` stays **missing** in `roadmap.json`. Effects are kept in the project and
not exported, and Studio says so.

The nearest possible backend (HS-027) would generate server code that sends dust and crit particles from
`native_send_particles`, with these limits:
- it is lossy: no size curves, drag, trails or per-particle timing;
- it needs a native mod and an authoritative level;
- it is not available at the pin.

That backend is planned, not built.

## Crystal Titan (SC-001)

The showcase stays at level 0. The impact spark is a building block for level 1 (*editable in Studio*) and level 2
(*rendered in the Studio preview*). The Titan's model, animation and entity are not built, and levels 3–5 need engine
contracts that do not exist.
